# Stack Profile — vanaila-chat v0.3.2

- **Language/runtime**: TypeScript 5.7 (ESM, `target: ESNext`), Node.js ≥ 22 (`engines` in package.json), pnpm ≥ 9. Rust (Tauri 2) for the desktop edition. Python 3 side-script for LoRA training.
- **Editions**: one frontend, two backends. **Web**: Hono backend over HTTP. **Desktop** (`src-tauri`, `com.vanaila.chat`): Rust commands over Tauri IPC with its own SQLite layer (`rusqlite`, `rusqlite_migration`). `src/frontend/lib/api.ts` picks IPC or HTTP per call; components should not `fetch('/api/…')` directly.
- **Backend-parity contract**: `contracts/api-shapes.json` lists the camelCase keys both backends must return; checked by `src/backend/__tests__/api-contract.test.ts` and `src-tauri/src/contract.rs`.
- **Backend framework**: Hono 4.6 served by `@hono/node-server`; entry `src/backend/index.ts`, app factory `src/backend/app.ts` (DI via `AppDependencies`, options via `AppOptions`).
- **Frontend**: React 19 + Vite 6; `marked` + `highlight.js` + `dompurify` for message rendering (forms, inputs and inline styles are stripped). Dev proxy = custom Vite plugin reading `.port`.
- **Database**: SQLite via `better-sqlite3` 12 (WAL, `foreign_keys=ON`), file `data/vanaila.sqlite`, override `DATABASE_PATH`. Desktop uses the XDG data dir.
- **Query layer**: no ORM. Hand-written SQL in `src/backend/services/db/*` (projects, chats, messages, feedback, codingSessions, memory, settings, skills); `DatabaseService` is a thin facade. Migrations 1–17 in `services/migrations.ts` (`schema_migrations` table; pre-migration databases are treated as v4). Desktop mirrors them as V1–V18 (V18 adds memory metadata/source).
- **Migration safety**: before pending migrations run on an existing database, both editions write `<data>/backups/<name>-pre-v<N>-<time>.sqlite` (`VACUUM INTO`), keeping the newest five.
- **Message history**: regenerate/edit mark replaced messages `superseded_at` (hidden from the conversation and search, kept for the answer-version switcher); `version_of` links regenerated answers. Chats have `archived`.
- **Auth**: none by default; the server binds `127.0.0.1`. Optional `VANAILA_ACCESS_TOKEN` gates every `/api` route except health/auth (Bearer header or HttpOnly SameSite=Strict cookie from `POST /api/auth`); a non-loopback `HOST` refuses to start without it. Provider keys (`OPENROUTER_API_KEY`, `OPENAI_API_KEY`, `NINE_ROUTER_API_KEY`, `CUSTOM_OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, or the `settings` table) are outbound only.
- **Request guards**: CORS limited to loopback origins; `originGuard` blocks cross-site writes (trusts `Sec-Fetch-Site: same-origin` only when a token is set); security headers via `secureHeaders`.
- **LLM providers**: `ProviderRegistry` over Ollama (local, auto-starts daemon), OpenRouter, OpenAI, NineRouter, custom OpenAI-compatible. Coding workspace harnesses: Pi (`@earendil-works/pi-coding-agent`) and DeepSeek Harness (`services/deepseekHarness.ts`).
- **Caching**: in-process only — rate-limiter Map, skills `SKILL.md` content in SQLite, embeddings (nomic-embed-text, 768-dim) in SQLite for cosine search, FTS5 index over messages.
- **Background jobs**: none. In-process timers only: rate-limiter sweep and per-tool timeouts (`run_command` children are killed at 180 s).
- **Rate limiting**: in-memory sliding window per route — 20/min `/api/chat`; 60/min `/api/models`, `/api/memory`; 10/min `/api/research`, `/api/skills/install`, `/api/skills/custom`, `/api/ab`; 30/min `/api/attachments`; 120/min `/api/fs`. `trustProxy` off (single anonymous bucket).
- **Deployment target**: local single machine (Linux/macOS/Windows) for web; Linux `.deb`/`.rpm`/`.AppImage` (+ PKGBUILD, Flatpak) for desktop. Backend picks `PORT` or a random 49152+ port and writes `.port`; `HOST` sets the bind address.
- **CI** (`.github/workflows`): `ci.yml` (lint, type-check, test, build), `desktop-linux.yml` (Rust/Tauri Linux build and tests), `release-desktop.yml` (on `v*` tags: tests, `tauri build`, checksums, GitHub Release).
- **HTTP entry points**: `/api/health`, `/api/auth` (+`/status`), `/api/config`, `/api/model-details`, `/api/projects`, `/api/chats`, `/api/messages` (+`/search`, `/supersede`, `/:id/feedback`, `/:id/versions`), `/api/export`, `/api/import`, `/api/pick-directory`, `/api/models` (+`/details`, `/pull` NDJSON), `/api/settings`, `/api/skills` (catalog/install/custom), `/api/personas`, `/api/research`, `/api/memory`, `/api/training` (stats/examples/export), `/api/ab` (+`/pick`), `/api/attachments`, `/api/fs`, `/api/git`, `/api/chat` (NDJSON streaming, `/approve`), `/api/coding` (harnesses/sessions/run).
- **Desktop shell**: tray menu (Show, New chat, Quit), global `Ctrl+Shift+Space` show/hide, daily GitHub Releases update notice (`check_for_update`).
- **Outbound network**: Ollama HTTP API, OpenAI-compatible endpoints, DuckDuckGo (`duck-duck-scrape`) + URL fetch for research (SSRF-checked), `raw.githubusercontent.com` for skill install, `api.github.com` release check (desktop).
- **CLI entry points**: `pnpm dev` (concurrently tsx-watch backend + vite), `pnpm desktop:dev` / `desktop:build`, `scripts/predev.js` (port reclaim; `predev.sh` POSIX twin), `scripts/backup-db.js`, `scripts/finetune/build-modelfile.js`, `scripts/finetune/train_lora.py` (`--mix-file`/`--mix-ratio`).
- **Agent tools exposed to models**: `search_web`, `read_url`, `read_file`, `list_directory`, `search_files`, `write_file`, `edit_file`, `run_command` (allowlisted git read-only subcommands, package-manager test/build/lint/type-check, file-read aliases; paths confined to the project root incl. symlinks; provider secrets not passed to children), `create_document`, `load_skill`. Writes, edits and commands need approval unless `require_tool_approval` is `false`.
- **Testing/lint**: Vitest 3 (node env; jsdom per file) — 38 backend + 15 frontend suites; `cargo test` for the desktop crate; ESLint 9 flat config, `--max-warnings=0`; `tsc --noEmit`.
